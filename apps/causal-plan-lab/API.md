# Causal Plan Lab engine contract

`core.mjs` and `scenarios.mjs` are dependency-free ES modules. All functions leave their arguments unchanged. `SCENARIOS` contains `{id,title,description,model,focus,trace}` entries; clone a model before editing.

- `validateModel(model)` returns `{ok,errors}`. Every place has a unique string id, condition/resource kind, and nonnegative safe-integer initial count. Every transition has a unique id, finite positive duration, positive integer maxFirings, at least one positive input arc, and nonnegative integer arc counts referencing existing places. A goal has at least one positive count. Counts must remain within safe-integer precision.
- `generate(model,{maxExecutions=1500,maxNodes=50000,allocation='fifo'})` returns `{executions,complete,stats,deadlocks,reason,errors}`. Executions are arrays of transition ids. Goal coverage is terminal: this enumerates all **first-goal prefixes**, within the declared per-transition firing bounds, when `complete` is true. No marking-state deduplication discards alternate witnesses. A generation budget never turns a partial trace into a complete plan. `reason` names a reached budget/invalid input or is null. Deadlocks include trace, final marking and either `no-enabled-transition` or `firing-bounds`; neither proves unbounded impossibility. Allocation does not change count-based enabling.
- `replay(model,ids,{allocation='fifo'})` returns `{ok,errors,events,edges,markings,finalMarking,goalReached,allocation}`. A legal partial trace can have `ok:true,goalReached:false`. A failed trace returns only the valid replayed prefix and `ok:false,goalReached:false`. Occurrences use `transitionId#occurrence`. Consumed/produced runs on events and labelled/count-bearing producer edges record the allocation witness. Initial tokens have producer null. Count snapshots are **atomic sequential firing snapshots**, not a concurrent timed marking simulation.
- `analyse(model,ids,{allocation='fifo',linearOrderLimit=10000})` adds strict transitive `order`, transitive-reduction `reducedEdges`, an exact labelled `tree` or null, `exactTree`, an induced `obstruction` if not representable, earliest `schedule`/`makespan`, and the naive earliest-start-group `stagedTree`. `stagedAdded` and `stagedRemoved` compare its order with the causal order; `stagedMakespan` recomputes barrier timing. `lostOrder` is a lawful causal linear order forbidden by that staged tree. `linearExtensions` counts causal orders; **`treeExtensions` counts staged-tree orders**, while `exactTreeExtensions` counts exact-tree orders when one exists. Counts are null if their enumeration limit is reached; completion flags and the limit are explicit. Empty traces can have the empty parallel tree. `boundedness.completeGoalPlan` states completion separately from legality or tree representability.
- `physicalOrder` closes only condition edges; `resourceEdges` keeps allocated reuse order distinct. A chosen resource witness can use one token twice even when spare capacity exists (notably LIFO). An earliest schedule is optimal for this fixed precedence witness and positive fixed durations; it does not establish a globally optimal resource schedule or unique interchangeable-token causality.
- Timing uses JavaScript floating-point numbers. An overflow or a positive duration that rounds away at its computed start makes analysis fail explicitly (`ok:false` with an error), including if only the staged proposal exceeds these numeric limits. Start-group comparisons use computed numeric start values; decimal arithmetic is subject to ordinary floating-point rounding.

Pure graph helpers:

The browser engine supports at most `MAX_EVENTS=32` event occurrences per trace. Replay/analysis reject longer input traces with a reviewable error. Generation uses `maxTraceLength=32` by default (an optional smaller positive limit is allowed); if a viable non-goal branch would continue past it, the search returns `complete:false`, reason `maxTraceLength`, and `stats.traceLimitBranches`. This is a computational limit, separate from the model's declared firing bounds. A goal reached exactly at the limit is accepted. `boundedness.maxEvents` and generation stats preserve this limit in exports.

- `closure(ids,edges)` → pair array `[[from,to],…]`, in supplied id order. Edges can be pairs or `{from,to}`. Unknown ids, duplicate ids and cycles throw.
- `decompose(ids,order)` → `{type:'task',id,label}` / `{type:'sequence'|'parallel',children}`, or null. Comparability components produce parallel blocks; incomparability components produce ordered sequence blocks, recursively. This is the restricted elementary event-block grammar, not a restriction on full symmetric monoidal process diagrams or all possible WBS conventions.
- `treeOrder(tree)` → pair array. Parallel adds no cross-child order; sequence orders every leaf in an earlier child before every leaf in a later one. Duplicate leaves throw.
- `linearOrders(ids,order,limit=10000)` → `{orders,complete,count,limit}`. At most limit orders are retained. The algorithm checks for an additional order before declaring truncation, so exactly-limit totals remain exact. A zero-event poset has one empty order.

An N certificate `{a,b,c,d,relations,absentRelations,induced:true}` has exactly `a<b`, `c<b`, `c<d` among its four induced events; absentRelations lists incomparable unordered pairs. The certificate describes the chosen allocation witness only. `engineVersion` is included for export/reopen evidence. All results are finite toy-model calculations under declared counts, goals, durations and firing bounds.
