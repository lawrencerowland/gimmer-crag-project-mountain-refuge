# Ancestry-family API

`families.mjs` exports `analyseFamily(model, trace, options={})`, `FAMILY_VERSION`, and `FAMILY_LIMITS`. It imports the existing pure causal-engine helpers and does not mutate its arguments. `family-scenarios.mjs` exports `FAMILY_SCENARIOS`, an array of `{id,title,description,model,trace,focus}`.

The input model uses the existing causal-lab schema. Its selected transition-id trace must legally reach its explicit goal for the first time at the final marking. The identity execution `[]` is accepted when the initial marking already covers the goal. Partial traces, traces continuing after reaching the goal, malformed data, and more than eight occurrences are rejected with `ok:false,errors`.

Every ancestry witness allocates consumed counts among available producer classes at each place. A class is an initial token (`producer:null`) or tokens from one event occurrence. Identical tokens within a class are not permuted or counted separately. Allocations at different places, to different consumers, or in different producer counts remain distinct, including when they induce the same event order. This is a producer-count quotient, not a claim of BD-process equivalence or canonical collective-token causality.

The family is **relative to the selected trace**. It enumerates allocations compatible with that trace, then takes the union of their event-order extensions. It need not include every legal count-level reordering of the same transition multiset. For example, two tasks borrowing and returning one shared resource admit input traces A,B and B,A, but the family selected by A,B contains only the ancestry A before B. Selecting the other trace is a separate analysis.

## Result

- `ok`, `errors`, `modelId`, `version`, `events`. Event entries contain `{id,transitionId,label,duration,index}` with distinct repeated-occurrence ids.
- `witnesses`: stable entries `{id,allocations,edges,order,reducedEdges,tree,exactTree,obstruction,schedule,makespan}`. Allocation entries are `{eventId,place,producer,count}` and include initial producer null. Edges retain `{from,to,place,kind,count}`. Orders are strict transitive pair arrays. Trees use the existing task/sequence/parallel grammar. Schedules contain `{id,start,end}`.
- `complete` covers ancestry enumeration. `reason` is null or the first reached ancestry budget/numeric boundary. `stats` reports searched states, accepted witnesses, retained allocation entries, distinct observed orders, visited permutations, language membership checks, and reached limits. `bounds` records every effective budget and supported model/event boundary.
- `classification`: `all`, `some`, or `none` exactly when ancestry enumeration finishes; otherwise `unknown`. `observed` reports `exactTreeWitnesses`, `nonExactTreeWitnesses` and `classification` (`all`, `some`, `none`, or `empty`) for the retained sample only.
- `distinctOrders` is an exact number when ancestry enumeration finishes, otherwise null. `observedDistinctOrders` always counts retained distinct causal orders.
- `mustOrder` (intersection) and `mayOrder` (union) are pair arrays only when ancestry enumeration finishes, otherwise null. `observedMustOrder` and `observedMayOrder` always describe retained witnesses.
- `language:{orders,count,observedCount,complete,observedComplete,reason,scope}`. `orders` are the discovered union of linear extensions, in stable event-id permutation order. `count` is null unless both ancestry and language enumeration finish. `observedCount` is the number retained. `observedComplete` means the language of retained witnesses was fully enumerated; `complete` additionally requires all ancestries. `reason` names a reached language budget or is null. **Language orders use all retained event occurrences and can satisfy the goal before their final occurrence.** First-goal selection applies to the input trace, not to this mathematical language; filtering alternative orders by first-goal timing would change the poset-extension construction.
- `summary:{dagExact,treeExact,tree,spuriousOrder,overconstraintOrder,unionCyclic}`. DAG/tree verdicts remain null unless `language.complete`. A DAG can represent the whole family language exactly iff the extensions of `mustOrder` equal that language. A `spuriousOrder` is accepted by the common relation but absent from the complete family language. `treeExact` additionally requires the common relation to decompose exactly in the restricted tree grammar; `tree` is supplied only in that case. `overconstraintOrder` is a family-language order excluded by the union relation. `unionCyclic` checks the complete union; in this fixed-trace construction its edges all follow the input trace, so a cycle should not arise.
- `minFinish`, `maxFinish` are exact extrema when ancestry enumeration finishes; otherwise null. `observedMinFinish` and `observedMaxFinish` report retained extrema. `timingScope` states that these range over each selected ancestry witness's **earliest** schedule. They are not bounds on arbitrarily delayed schedules, probabilities, or an uncertainty model.

## Explicit budgets

Defaults: `maxWitnesses=2048`, `maxStates=50000`, `maxAllocationEntries=65536`, `maxWitnessCharacters=4000000`, `maxLanguageOrders=40320`, `maxLanguageChecks=2000000`, `maxLanguageCharacters=4000000`. Options are positive safe integers, bounded above by the corresponding hard limits in `FAMILY_LIMITS`. Models support at most 64 places, 32 transitions and 8 selected event occurrences.

`maxStates` counts entered partial allocation-search states, including distribution choices; it bounds multiplicity exploration even for large integer counts. `maxWitnesses` and `maxAllocationEntries` bound retained witness data. An additional witness is sought before a witness-cap truncation is declared, so exactly-at-cap exhaustive results can be complete. `maxLanguageOrders` bounds inspected event permutations, not just accepted words. `maxLanguageChecks` bounds comparisons against distinct witnessed orders. At most 8! permutations exist. Language limits are reported separately from ancestry completeness. A budget never certifies impossibility, universal tree representability, or a complete language.

`maxWitnessCharacters` bounds the sum of `JSON.stringify(witness).length` for retained witnesses; reaching it truncates ancestry enumeration. `maxLanguageCharacters` similarly bounds the sum of serialized retained word lengths, truncating language enumeration. Both use UTF-16 string characters, not byte counts. Stats expose `witnessCharacters` and `languageCharacters`. These additional limits prevent long user-supplied ids or labels from multiplying into oversized worker results even when the event count is small. They bound these collections separately, not the complete export file including model and metadata.

Durations use the causal engine's finite floating-point policy: nonfinite sums or a positive duration erased by rounding return a reviewable error. No timing certificate is emitted as complete after such an error.
